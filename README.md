# Bar do Pezao

Site do bar com:

- home de divulgacao em `/`
- cardapio digital geral em `/cardapio`
- painel admin protegido em `/admin/login` e `/admin/painel`

## Rodar

```bash
npm install
npm run dev
```

## Estrutura recomendada

Voce pode deixar tudo neste mesmo repositorio. Nao precisa criar outro projeto so porque o cardapio fica em um link separado.

Exemplo:

- `https://seu-dominio.com/` -> site principal
- `https://seu-dominio.com/cardapio` -> cardapio digital geral
- `https://seu-dominio.com/admin/login` -> login do admin

Isso simplifica deploy, manutencao, dominio e evolucao do sistema.

## QR Code

O cardapio agora e unico para toda a casa. Gere um unico QR Code apontando para `/cardapio` e use em todas as mesas, no balcao e na divulgacao.

A rota antiga `/mesa/:id` redireciona automaticamente para `/cardapio`.

## Admin e seguranca

O front agora nao usa senha hardcoded.

Configure:

- `VITE_SUPABASE_URL`
- `VITE_SUPABASE_ANON_KEY`
- `VITE_ADMIN_EMAILS`

Exemplo de `VITE_ADMIN_EMAILS`:

```env
VITE_ADMIN_EMAILS=admin@pezao.com,gerente@pezao.com
```

Fluxo esperado:

1. Crie os usuarios administradores no Supabase Auth.
2. Use senhas fortes no proprio Supabase.
3. Liste os e-mails autorizados em `VITE_ADMIN_EMAILS`.
4. O usuario precisa ter login valido e estar nessa lista para abrir `/admin/painel`.

## Supabase

O app usa `src/lib/supabaseClient.js` e espera estas tabelas:

```sql
create table products (
  id text primary key,
  name text not null,
  category text not null,
  description text,
  price numeric not null,
  image text,
  available boolean default true
);

create table orders (
  id bigint generated by default as identity primary key,
  status text not null default 'Pendente',
  total numeric not null,
  items jsonb not null,
  created_at timestamptz default now()
);

create table service_calls (
  id bigint generated by default as identity primary key,
  type text not null,
  status text not null default 'Pendente',
  created_at timestamptz default now()
);
```

Ative Realtime para `orders`.

Antes de publicar, ajuste as politicas RLS para:

- cliente poder ler produtos disponiveis
- cliente poder inserir pedidos e chamadas de servico
- admin autenticado poder ler e atualizar pedidos e produtos

Sem dados em `products`, o sistema usa itens demonstrativos para facilitar o desenvolvimento local.
